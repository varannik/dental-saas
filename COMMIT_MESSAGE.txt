feat(docker,auth,gateway,web): Docker API stack, login/session fixes, tenant UI MVP

Run the full API surface in Docker (`make docker-up-apps`), fix login failures after
successful register (Redis + `sessions` + clearer errors), harden gateway CORS for local
Next.js, and ship web tenant-management phases 1–3 with atomic tenant creation on users.

Docker & local dev

- **`docker-compose.yml`** Profile `apps`: api-gateway (:4000), auth, users, clinical; auth
  overrides `DATABASE_URL` → `postgres:5432`, `REDIS_URL` → `redis://redis:6379`,
  `NODE_ENV: development` (actionable login error bodies).
- **Service Dockerfiles** (auth, users, clinical, api-gateway): reproducible `pnpm install`,
  workspace package stubs, Vitest excluded from gateway build; auth runtime no longer forces
  `NODE_ENV=production`.
- **Makefile** `docker-up-apps`, `verify-docker-web`, `diagnose-auth-login`; removed host
  `start-services` flow in favor of Compose.
- **`start-apps.sh`** Warns when `public.sessions` is missing (prompts `make db-migrate`).
- **`scripts/dev/diagnose-auth-login.sh`** Checks sessions table, auth env, Redis from auth
  container, optional direct/gateway login curl.
- **`scripts/dev/verify-docker-web-stack.sh`** Docker API + CORS + web gateway target checks.
- **`.env.example`** Notes on `DATABASE_URL` override and Docker vs host ports.

API gateway

- **`apps/api-gateway/Dockerfile`** + compose service; upstream URLs `http://auth:4001`, etc.
- **`plugins/cors.ts`** Reflect localhost/LAN origins when `CORS_ORIGINS` is empty; `onSend`
  hook; tests in `plugins/__tests__/cors.test.ts`.
- **`routes/auth.proxy.ts`** Correct upstream path when `request.url` is `/auth/*` under
  `/api/v1` prefix.

Auth service

- **`auth.service.ts`** Invalid credentials → **401** (`statusCode`), not opaque **500**.
- **`session.service.ts`** Explicit Redis connect/ping; rollback DB session row if Redis `SET`
  fails; hint when `sessions` table is missing.
- **`error-response.ts`** **4xx** expose real `error`/`message`; **503** for Redis/DB session
  infra in dev; **5xx** stay generic in production.
- **`services/auth/Dockerfile`** Align with other service images.

Users service

- **`verify-access-token.ts`** JWT verification for protected routes.
- **`POST /tenants/with-membership`** Atomic tenant + creator `ADMIN` in `user_tenants`.
- **`index.ts`** `isDirectRun` guard (no auto-listen under Vitest).
- **`vitest.config.ts`** + tests for membership route and token verify.

Web app (tenant phases 1–3)

- **`auth-storage.ts`**, **`auth-session.ts`**, **`auth.store.ts`**: persist access token +
  active `tenantId`; reconcile via **`GET /auth/me`** in dashboard shell.
- **`use-active-tenant.ts`**, header/shell: show active tenant; **`getDefaultTenantId()`**
  (`NEXT_PUBLIC_DEFAULT_TENANT_ID` or demo UUID).
- **Login/register** use default tenant; register/login error bodies read `message` then
  `error`; **`login-email-storage.ts`** for last email.
- **Settings** “Create organization” → `POST /api/v1/tenants/with-membership` + re-login.
- **`api-client.ts`** 401 handling; **`vitest.config.mts`** + storage/constants tests;
  **`apps/web/.env.example`**.

Gateway smoke & DB tooling

- **`gateway-smoke-checks.sh`** Reject `.env*` / shell `DATABASE_URL` on :5432; verify
  `public.users` before HTTP; document Docker :5433 vs native :5432.
- **`scripts/database/tests/list-users-tenants.sh`** List tenants, users, `user_tenants`.

Docs

- **`docs/ux/web-tenant-management.md`** Phased plan; status notes for phases 1–3 in repo
  and remaining switcher/invite work.
